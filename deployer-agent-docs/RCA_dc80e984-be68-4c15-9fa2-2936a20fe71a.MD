## Root cause
Primary: the summary endpoint reads `db.attendance` for the month with `.to_list(20000)`, and **every active month holds 31k–37k rows (all > 20,000)** → silent truncation → incomplete HR Attendance Summary, worst under "All Locations & Projects".
Secondary (correctness): the `employees.status == "inactive"` exclusion never matches — real values are `active/Active/null/exited`, so the intended exclusion (7 "exited") does not happen, and the `Active`/`active` case split can break status logic.
Contributing (stability): the large in-memory loads correlate with pod OOMKills (exit 137, 2 restarts) on tier_0's 512Mi limit and multi-second response times.
Contributing (ingestion): Google-sheet attendance sync is failing (scheduled) / partial (manual), independently leaving data missing.
Could not verify: duplicate (employee_id,date) groups — tool has no aggregate.
